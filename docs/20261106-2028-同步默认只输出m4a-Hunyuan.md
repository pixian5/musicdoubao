# 同步默认只输出 m4a（2026-11-06）

## 背景与决策

`sync_voice_memos.py` 早期对 `.qta` 录音的处理是「原样同步 `.qta` + 额外转一份 `.m4a`」，
即 Dropbox 里同时保留 `xxx.qta` 和 `xxx.m4a`。

用户 2026-11-06 明确要求：**以后默认只输出 m4a**。理由：`.qta` 是较新 macOS 语音备忘录
专有封装，跨平台播放不便；`.m4a`（AAC）才是通用格式。原始 `.qta` 在本机
`~/Library/Group Containers/group.com.apple.VoiceMemos.shared/Recordings` 始终保留，
Dropbox 只是备份副本，没必要再存一份专有格式。

## 改了什么

1. 新增开关 `KEEP_QTA_ORIGINAL`（默认 `False`）：
   - 可用环境变量 `VOICE_MEMOS_KEEP_QTA=1` 打开；
   - 也可用命令行参数 `--keep-qta` 打开（在 `main()` 中通过 `sync_once(..., keep_qta=...)` 传入）。
2. 默认（`KEEP_QTA_ORIGINAL=False`）行为：
   - `.m4a` 源：照旧复制为 `.m4a`。
   - `.qta` 源：用 ffmpeg 转码为 `.m4a` 作为**主输出**写入目标目录；**不再写入原始 `.qta`**。
3. 历史残留清理（一次性过渡）：
   - 之前已同步进 Dropbox 的 `.qta` 原始文件，在本次同步后统一移入 `回收站/` 子目录
     （安全移除，可恢复，非真正删除），仅保留对应的 `.m4a`。
4. 保留 `--keep-qta` 路径：打开后恢复旧行为（主输出为 `.qta`，额外补一份 `.m4a`）。

## 关键代码位置（便于以后回溯）

- 开关定义：`sync_voice_memos.py` 顶部常量 `KEEP_QTA_ORIGINAL`（读环境变量）。
- 逐条判断：`sync_once()` 内 `source_is_qta` / `output_m4a_only` 两个标志。
- 命名归一：在 m4a-only 模式下把主输出扩展名从 `.qta` 强制改为 `.m4a`
  （出现在 `target_path` 初次确定处、以及碰撞重解名之后两处）。
- 写入分支：`sync_once()` 末尾的 `if output_m4a_only:` 用 `convert_qta_to_m4a()` 代替 `atomic_copy2()`；
  非 m4a-only 走原复制逻辑。
- 残留清理：`output_m4a_only` 且成功生成 `.m4a` 后，扫描 `(目标目录, 最近删除/)` 中同名 `.qta`
  并 `move_to_trash()` 到 `回收站/`。
- 兼容性护栏：m4a-only 模式下跳过「旧 `.qta` 直接 rename 成 `.m4a`」的兼容逻辑
  （那样只改名不转码，文件内容仍是 qta 封装，会误导播放器），改为重新转码。

## 验证结果（2026-11-06 实跑）

运行前 Dropbox「录音机」目录：
- 顶层 `.qta` = 53，最近删除 `.qta` = 2，回收站 `.qta` = 0（合计 55，与源/库一致）。

运行后：
- 顶层 `.qta` = 0，最近删除 `.qta` = 0，回收站 `.qta` = 55。
- 输出 `.m4a` 总数保持 603（顶层）+ 最近删除内若干，全部为通用格式。
- 同步报告：`skipped=609, trashed=55, converted=0, convert_failed=0`
  （`converted=0` 是因为此前已为 55 条 `.qta` 生成过 `.m4a` 兄弟文件，本次仅清理原件）。

结论：输出目录已为 **m4a 专属**；55 个原始 `.qta` 安全移入回收站（可恢复），本机原件不受影响。
后续新录的 `.qta` 将只生成 `.m4a`，不再产生 `.qta` 输出。

## 恢复原始 `.qta` 输出的方法

若以后想同时保留原始 `.qta`，二选一：
- 临时：`VOICE_MEMOS_KEEP_QTA=1 uv run python sync_voice_memos.py`
- 或：`uv run python sync_voice_memos.py --keep-qta`
并从 `回收站/` 把需要的 `.qta` 移回即可。
