# 同步脚本支持 .qta 格式修复

> 生成时间：2026-11-06 19:16 ｜ 模型：Hunyuan ｜ 项目：music（语音备忘录同步工具）

## 问题现象

用户发现最近一批语音备忘录没有同步到 Dropbox，例如「紫薇路蔡伦路交叉口双创产业基地一期L212 2」。
但脚本运行结果显示 `copied: 0 / skipped: 554`，仿佛所有录音都已同步，与用户观察矛盾。

## 根因

macOS 较新版本的语音备忘录（本机为 macOS 27）会把录音存成 **`.qta`** 新格式，旧录音仍是 **`.m4a`**。
脚本原本有两处只认 `.m4a`：

1. 数据库查询过滤：`WHERE ZPATH IS NOT NULL AND ZPATH LIKE '%.m4a'`
   —— 所有 `.qta` 记录在读取阶段就被排除，根本不会进入同步流程。
2. 文件名校验函数 `is_m4a_name()` 只判断 `.m4a` 后缀，多处用来「是否可同步的录音文件」判断。
3. 查找同名已有文件时用 `target_dir.glob("*.m4a")`，只匹配 `.m4a`。

数据库实测分布：共 609 条，其中 `.m4a` 554 条（已同步）、`.qta` 55 条（全部漏掉）。
紫薇路那条本地实有 186MB 的 `.qta` 文件，确认只是没被同步出去。

## 修复内容

- 新增常量 `SUPPORTED_AUDIO_EXTS = (".m4a", ".qta")`，把 `is_m4a_name()` 重命名为 `is_audio_name()`，扩展为同时支持两种后缀，并全文替换调用。
- 数据库查询改为 `AND (ZPATH LIKE '%.m4a' OR ZPATH LIKE '%.qta')`。
- `find_compat_existing_file()` 改为遍历目录后用 `is_audio_name()` 过滤，不再局限于 `.m4a`。

## 验证结果

- 语法编译通过；`is_m4a_name` 残留 0 处。
- 逻辑验证：`load_recordings()` 现返回 609 条（.m4a=554, .qta=55），目标文件名生成正确。
- 真实同步：`recordings=609, copied=55, skipped=554, trashed=0`，55 条 `.qta` 全部进入 Dropbox（含用户点名那条；其中 2 条因「最近删除」状态落在 `最近删除/` 子目录），无任何文件被删除。
- Dropbox 目标目录已能搜到「紫薇路蔡伦路交叉口双创产业基地一期L212 2+20261023 142516-00C02CA2.qta」。

## 注意事项（保留，非本次改动）

- `.qta` 是 Apple 较新专有格式，在 Mac 上可直接回放；在 Windows / 安卓上可能打不开（仅作存储备份无碍）。若需跨平台可播，另行用 ffmpeg 转码（未做，当时选择「原样同步」方案）。
- 55 条 `.qta` 体积较大（单条可达约 186MB），会占用相应 Dropbox 空间。
- 本机环境：用 `uv` 管理虚拟环境（Python 3.14.0），运行命令为 `uv run python sync_voice_memos.py`；旧 `.venv` 曾因系统 Python 3.14 框架被移除而失效，已用 uv 重建。

## 后续新增：.qta 额外转 .m4a（2026-11-06 约 20:10）

用户要求在原样保留 .qta 的基础上，再为每条 .qta 额外生成一份 .m4a（AAC），使手机 / Windows 也能直接播放。

- 实现：在 `sync_once` 复制/确认源文件后，若源为 `.qta` 且目标 `.m4a` 尚不存在，调用 `ffmpeg` 转换。
- 转换策略：优先 `-map 0:a:0 -c:a copy -f mp4`（无损复制内部已有的 AAC 流，仅重新封装）；若失败则回退 `-c:a aac -b:a 192k -f mp4` 重新编码。
- 原始 `.qta` 文件不会被改动，Dropbox 中每条录音同时保留 `.qta` + `.m4a` 两份。
- 验证：55 条 `.qta` 全部成功转出 `.m4a`（重跑显示 `converted: 0, convert_failed: 0`，说明首次运行已转完，二次运行无需重转，且无失败）。
- 修复点：`ffmpeg` 必须显式指定 `-f mp4`，否则临时文件扩展名 `.m4a.partial-<pid>` 会让 ffmpeg 无法推断容器格式而失败。
- `main()` 的 JSON 打印补充了 `converted` / `convert_failed` 两个字段，便于观测。
